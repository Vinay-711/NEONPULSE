# Milestone v1.0: NeoPulse MVP

**Status:** ✅ SHIPPED 2026-04-26
**Phases:** 01-04
**Total Plans:** 4

## Overview

Initial release of the NeoPulse non-contact neonatal monitoring system. Transitioned from client-side simulation to a robust FastAPI backend with Server-Sent Events (SSE) telemetry, real-time EVM signal extraction, and ML-based apnea classification.

## Phases

### Phase 01: Core Signal Pipeline

**Goal**: Establish the foundational Eulerian Video Magnification (EVM) pipeline for extracting physiological signals.
**Depends on**: None
**Plans**: 1 plan

Plans:

- [x] 01-01: Core EVM Engine & Signal Routing

**Details:**
Set up real-time video capture framework. Implement spatial decomposition and temporal bandpass filtering (0.1-0.8Hz for RR, 0.8-3.0Hz for HR). Extract raw 1D signal arrays from video frames.

### Phase 02: Rate Estimation & Heuristics

**Goal**: Convert raw signals into actionable BPM and breathing rates with clinical thresholds.
**Depends on**: 01
**Plans**: 1 plan

Plans:

- [x] 02-01: Rate Estimation (Peaks) & Rule-based Alert Fallback

**Details:**
Implement peak detection algorithms over the filtered signals. Calculate signal confidence scores based on interval standard deviations. Build the deterministic rule-based alert engine (Normal, Caution, Emergency).

### Phase 03: AI Integration & Benchmarking

**Goal**: Train and integrate the machine learning classifier using PhysioNet datasets.
**Depends on**: 02
**Plans**: 1 plan

Plans:

- [x] 03-01: Classifier Training & EVM Benchmarking

**Details:**
Extract features (mean HR, std HR, RR interval) from Apnea-ECG/NInFEA datasets. Train and deploy the Random Forest classifier. Validate system accuracy (MAE, RMSE, Pearson R) against ground truth ECG.

### Phase 04: Edge Deployment & UI

**Goal**: Finalize the user interface and ensure offline capability.
**Depends on**: 03
**Plans**: 1 plan

Plans:

- [x] 04-01: UI Frontend & Real-time Backend Synchronization (SSE)

Build the Doctor/Parent Dashboard visualizing live waveforms. Optimize the processing loop to run efficiently on mobile/edge hardware.

---

## Milestone Summary

**Key Decisions:**
- Decision: Use SSE (Server-Sent Events) over WebSockets (Rationale: Unidirectional data flow from backend to frontend is perfect for telemetry and simpler to implement).
- Decision: Offload EVM calculation to Backend (Rationale: Client-side JS was too heavy; Python enables robust SciPy usage).
- Decision: Fallback Rule-Engine (Rationale: Ensures alerts function even if Random Forest inference fails).

**Technical Debt Incurred:**
- The AR overlay overlay in `neopulse.html` might desynchronize slightly if the video stream lags behind the SSE data ticks. Needs optimization in v1.1.
